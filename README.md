# Surge Geosite Enhance

A Cloudflare Worker that serves Loyalsoldier's geosite/geoip datasets as Surge-friendly rulesets, JSON indexes, and SRS bundles. The project keeps the data in sync automatically so Surge users can point to a single Worker origin instead of mirroring the upstream repository or distributing large dat files.

## Why it helps

- Converts upstream `geosite.dat` and `geoip.dat` into Surge-compatible plain-text rulesets on demand.
- Publishes `.srs` bundles alongside JSON for both geosite and geoip groups.
- Caches generated artifacts in R2 and Workers KV to minimize cold starts and bandwidth.
- Ships with scripts to regenerate data, update SRS bundles, and sync a D1 database for fast lookups.

## How to use the hosted service

### Geosite rulesets

- Endpoint: `GET https://direct.sleepstars.de/geosite/<name>[@filter]`
- Filters: `@cn`, `@!cn`, or specific region tags from the source data.
- Example: `https://direct.sleepstars.de/geosite/apple@cn`
- SRS bundle: `https://direct.sleepstars.de/srs-geosite/<name>.srs`

### GeoIP rulesets

- Endpoint: `GET https://direct.sleepstars.de/geoip/<name>[@v4|@v6]`
- Example: `https://direct.sleepstars.de/geoip/cn@v4`
- SRS bundle: `https://direct.sleepstars.de/srs-geoip/<name>.srs`

### Index endpoints

- Geosite JSON index: `https://direct.sleepstars.de/geosite`
- GeoIP JSON index: `https://direct.sleepstars.de/geoip`

## Prebuilt listings

The generated Markdown tables stay versioned in Git for convenient browsing and fetching:

- Geosite listing: [data_files.md](https://github.com/Sleepstars/Surge-Geosite-Enhance/blob/main/data_files.md)
- GeoIP listing: [geoip_files.md](https://github.com/Sleepstars/Surge-Geosite-Enhance/blob/main/geoip_files.md)

These files are regenerated by the automation pipeline and keep the worker's URL structure in sync with the published artifacts.

## Local development

1. Install prerequisites: Node.js 20.18+ (22 LTS recommended), npm, and Wrangler 4.x.
2. Install dependencies: `npm install`.
3. Run the worker locally: `npm run dev` (listens on `http://localhost:8787`).
4. Try requests such as `GET /geosite/apple@cn` to validate rule rendering.

## Deployment

- Deploy to Cloudflare Workers with `npm run deploy` (Wrangler will minify the bundle).
- Before deploying, configure required bindings in `wrangler.toml` (KV namespaces, R2 bucket, D1 database) and set the corresponding secrets using `wrangler secret put`.

## Regenerating data manually

- Rebuild geosite artifacts: `npm run build:geosite` (updates `index.json`, `dist/geosite-json`, and `data_files.md`).
- Rebuild geoip artifacts: `npm run build:geoip` (updates `geoip-index.json`, `dist/geoip-json`, and `geoip_files.md`).
- Generate SRS bundles: `npm run build:srs` and `npm run build:srs-geoip`.
- Update the D1 seed SQL: `npm run build:d1`.

For R2 synchronization or KV uploads outside CI, use `npm run r2:sync`, `npm run kv:put:index`, and `npm run kv:put:geoip-index` as needed.

## Additional tooling

The `misc/wechat` directory contains Bun scripts for producing a WeChat IPv4 allowlist. Run `bun install` in that directory, then `KEY=your_api_key bun run fetchv4.ts` followed by `bun run genv4.ts` to refresh the list.
